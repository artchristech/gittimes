mpv Makes Its libplacebo-Powered Renderer the Default in Version 0.41 🔗

Release also prefers Vulkan hardware decoding and adds native AAudio output for Android, cutting reliance on JNI glue.

mpv-player/mpv · C · 37.4k stars Est. 2012 · Latest: v0.41.0

mpv is a command-line media player built on FFmpeg for decoding and a shader-based rendering pipeline. Its latest release, **v0.

41.0**, changes what most users will actually see: the libplacebo-based gpu-next video output is now the default, replacing gpu. That means color management, scaling, and subtitle blending run through the newer path unless users opt out.

The release also reorders hardware decoding preferences. vd_lavc now tries Vulkan first when available, and prefers non-copy hwdec paths before falling back to -copy variants. Playback on capable systems should avoid unnecessary GPU-to-CPU transfers.

Platform work is broad:

  • Wayland gains color representation support (wp-color-representation-v1), tablet input, and clipboard writing.
  • X11 gets a dedicated clipboard backend.
  • Android receives a native AAudio audio backend, removing the JNI layer from the audio path.
  • Linux can read ambient light from sysfs for the ambient-light property.
  • Windows ships mpv-register and mpv-unregister helpers to associate mpv with media file types.
  • A new context_menu.lua script adds right-click menus.

Builders packaging mpv or writing scripts should note the dependency floor: this release requires FFmpeg 6.1+ and libplacebo 6.338.2+. Older distribution packages will not build cleanly.

The catch: The default switch to gpu-next is the biggest behavioral change, and it lands on a renderer whose output differs from gpu in color handling. Users with tuned configurations or custom shaders may see visual differences. The project also carries 1,156 open issues, so the switch is only as stable as the bug queue behind it. Pin --vo=gpu if your workflow depends on the old output.

Use Cases
  • Video editors previewing footage with accurate color management on Wayland desktops.
  • Android developers embedding mpv and wanting AAudio output without JNI overhead.
  • Power users scripting playback workflows with Lua and customizing right-click menus.

Open-Source Tool Lets Windows, Mac and Linux Machines Bond Multiple Internet Links 🔗

Per-connection balancing across Wi-Fi, Ethernet and phone tethers lifts multi-download throughput to about 232–303 Mbit/s in one test.

rohit267/net-merge · Go · 679 stars 4d old

net-merge combines every internet connection a machine has and spreads traffic across them. It runs on Windows, macOS and Linux, is free, and requires no account, server or VPN.

It is written in Go and creates a TUN interface (Wintun on Windows) to route traffic.

Balancing happens per connection, not per byte. Each new connection is assigned to one of your links, so an app that opens many connections spreads them across all of them. In a test combining Wi-Fi, an Android USB tether and an iPhone hotspot, nine simultaneous downloads reached 232–303 Mbit/s. The fastest link alone delivered about 121 Mbit/s.

The design has practical safeguards. Faster links receive more connections, and a link without internet access receives none until it recovers. Release 0.3.0 adds native packages (.deb, .rpm, .apk, Arch) for a wide range of Linux CPUs, including Raspberry Pi, and pauses merging automatically when only one connection works.

Overall CPU cost is light, roughly 0.18 cores per 100 Mbit/s, according to the project.

The catch: Speedups apply only across multiple connections. A single large download stays on one link and gains nothing. The Windows installer is not yet code-signed, so SmartScreen will warn users, and the project shows three open issues and an early 0.x version number.

Use Cases
  • Gamers accelerating Steam and console downloads over several links
  • Developers speeding up multi-connection package and system updates
  • Remote workers combining Wi-Fi with phone hotspots as backup bandwidth
  • Download-manager users aggregating torrents and parallel file transfers

Latest release also reads Gradle multi-module builds and retries GitHub lookups when a mirror goes down

jdx/mise · Rust · 35.1k stars Est. 2023

The mise tool manager, a Rust project now in its fourth year, installs a project's tools, sets its environment variables and runs its tasks from one mise.toml file.

The latest release (v2026.10.12) adds a change builders on Python stacks will notice first.

What changed:

  • Per-tool Python for pypi: tools. Set python = "3.12" on a tool such as black, and mise installs that runtime for that tool alone. Your shell's default Python stays untouched.
  • Gradle discovery. mise tasks graph and mise run --affected now read include entries in settings.gradle files.
  • GitHub fallback. Lookups retry on api.github.com when the version mirror is down.

Changing a tool's python builds a fresh environment, and a failed build leaves the old one intact.

The catch: the project has 13 open issues and its last push came the same day as this review, so the release cadence is active but the per-tool Python feature is new and untested at scale.

Use Cases

  • CI maintainers wanting one config file for tools, env vars and tasks.
