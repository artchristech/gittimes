Open-Source Tool Lets Your Laptop Pool Every Network Connection It Has 🔗

net-merge splits traffic across Wi-Fi, Ethernet and phone tethers at once, with a free Go codebase that runs on Windows, macOS and Linux.

rohit267/net-merge · Go · ▲ 267 in 1d 5d old · Latest: v0.3.0

Most people sit on one internet connection at a time, even when several are within reach. net-merge, a Go project on GitHub, changes that by using all of a machine's network adapters together.

Wi-Fi, Ethernet, USB tethers and phone hotspots combine into a single pool, and the speed of each link adds up for multi-connection workloads.

The mechanism is per-connection load balancing rather than packet splitting. Each new TCP or UDP connection is assigned to one link, so an application that opens many connections spreads them across every available path. Steam downloads, browsers, cloud uploads and torrent clients benefit most. The project's own test, run with Wi-Fi, an Android USB tether and an iPhone hotspot, reported 232 to 303 Mbit/s across nine simultaneous downloads, against roughly 121 Mbit/s for the fastest link alone.

Several design choices stand out. Faster links receive more connections, and a link without internet access receives none until it recovers. The tool sits on TUN and Wintun interfaces, so applications need no proxy configuration. If net-merge crashes, the machine's normal routing keeps working. It claims about 0.18 CPU cores per 100 Mbit/s and carries no account, server or VPN dependency.

Release 0.3.0 adds native packages for Debian, Fedora, openSUSE, Alpine and Arch across nine CPU architectures, including Raspberry Pi targets, and pauses merging automatically when fewer than two links work. Installation is a single paste into a terminal or PowerShell.

The catch: A single large file over a single connection will not get faster, because each connection rides one link. The project has four open issues, the Windows installer is not yet code-signed and triggers SmartScreen warnings, and the project is young at version 0.3.0. Builders should test failover behavior on their own networks before relying on it for anything important.

Why this leads today Bandwidth aggregation is an old idea, but a single open-source TUN layer working across three desktop systems puts it within reach of everyday builders, a more practical change than a placeholder repo or niche benchmark.

Use Cases
  • Gamers pooling Wi-Fi and phone hotspots to speed up Steam downloads.
  • Remote workers combining Ethernet and tethered phones for faster cloud uploads.
  • Raspberry Pi builders aggregating multiple links on ARM-based gateway devices.

Native PC Port Lets Gamers Run PS4 Title inFAMOUS Second Son Without Emulating the CPU 🔗

Community project reimplements PS4 system layer and translates GPU calls to Vulkan, with motion-sensor emulation and Linux and Windows builds.

HayatoG/iss_pc · C++ · 533 stars 4d old

A community project called iss_pc is porting inFAMOUS Second Son (PS4, CUSA00223, base 1.00 plus 1.

07 update) to native PC. The original game code runs directly on the host processor. The PS4 system environment is reimplemented in software, and the GPU workload is translated to Vulkan. Because the CPU is not emulated, the approach avoids the overhead that slows conventional console emulators.

The project ships no game files. Users must dump their own copy from a PS4. The core is shared with ports of The Last Guardian and Gravity Rush 2, and the project reports the game reaches gameplay and the first chapters.

Recent builds add a Qt Quick launcher, a save-management system with pre-launch backups and .zip export, and twelve experimental fixes, labelled BP01–BP12, that were backported from other PS4 ports and the shadPS4 project. A fix for flickering lights and light bleeding through characters was confirmed on both Windows and Linux. Motion-sensor and touchpad input are emulated for non-Sony controllers through L3+R3 toggling.

Builds are available for Linux x86-64 (glibc 2.39+) and Windows 10/11.

The catch: Performance remains unstable, at roughly 20–30 FPS on an RTX 2060, and known rendering faults persist. The tracker holds 158 open issues, and the project is still labelled in development, so it is not a finished replacement for the original hardware.

  • PC gamers who own a PS4 copy and want native playback of inFAMOUS Second Son.
  • Preservation researchers studying PS4 system reimplementation and native console-port techniques.
  • Linux developers interested in Vulkan-based GPU translation layers for console software.

Blender Gets an AI Copilot That Edits Scenes Through Chat 🔗

Open-source add-on lets artists and developers route OpenAI, Claude, Gemini, or local Ollama models into Blender's scene, materials, and export tools.

LiCinCan/blender-ai-mcp-addon · Python · 723 stars 2d old

The mcp-for-blender-pro add-on puts an AI assistant inside Blender. It inspects the open scene, builds objects, edits materials, finds assets and runs multi-step tasks, with each action shown in a sidebar chat and checked in the viewport.

Larger jobs run through a Team chain. A manager splits the request into assignments, workers perform scene operations one at a time, and reviewers approve or send back findings. A blocked task gets one correction attempt before the workflow stops.

Rust Headless Browser Gives AI Agents a Lean Web Runtime 🔗

Moli speaks CDP, WebDriver Classic and BiDi from one endpoint, and renders pages on demand to keep memory footprints small.

lexmount/moli · Rust · 19.4k stars 2mo old

Moli, a headless browser written in Rust, is aimed squarely at AI agents that need to fetch pages, extract content, and drive real web interactions. It runs on Linux, macOS and Windows, and exposes a single endpoint that speaks three automation protocols: CDP, WebDriver Classic and WebDriver BiDi.

Its design choice is on-demand layout and rendering. Pages are parsed and laid out only when a task requires it, which keeps the resource footprint light compared with a full desktop engine.

Agents can request output as Markdown, as a compact semantic tree, or as PNG and PDF exports. Explicit interactions are handled through --eval combined with --dump, so only the supplied expression changes page state.

Recent releases focus on navigation and renderer correctness, including fixes to Fetch configuration during navigation and detached-node resolution.

The catch: with 383 open issues and a young codebase, a builder should test Moli against their own target sites before trusting it in production.

Kaku Lets You Reach Your Mac's Terminal From Any Browser 🔗

Version 0.24.0 adds remote access, one-time pairing and browser uploads for running AI coding sessions

tw93/Kaku · Rust · 6.1k stars 8mo old

The latest release of Kaku, a macOS terminal built on WezTerm, lets builders open their Mac's terminals in a browser on another machine. Running kaku remote exposes existing sessions, including ones already running Claude Code or Codex.

Access works through a few mechanisms:

  • Pairing: each link binds to one browser and works once. A bookmark reopens the page afterwards.
  • Relay: the relay forwards only content encrypted between the browser and the Mac.
  • Web terminal: tabs, splits and copy-paste match the native app. Files dropped on the page upload to the Mac, and Cmd+Click on a path downloads it.

Kaku ships with JetBrains Mono, automatic themes, shell completion and optional AI command suggestions, which you configure with your own service.

The catch: the project has one open issue and its last release arrived months ago, so the remote relay's security and reliability under real use remain unproven.

Single-File WebGPU Ocean Renders Sunset Sea Without Any Engine 🔗

Six FFT cascades simulate waves from kilometre swells down to millimetre ripples in one 61 KB page

Noniv/web-ocean · HTML · 602 stars 1d old

A new GitHub project, Noniv/web-ocean, renders a real-time sunset sea in the browser using nothing but WebGPU. It has no engine and no rendering library.

The whole scene opens from a single HTML file in recent Chrome.

The renderer runs a Tessendorf FFT simulation across six cascades of 256 by 256 samples. Wavelengths span roughly a kilometre down to a few millimetres, which is what produces the sun sparkle near the camera. The mesh is a 17-level CDLOD quadtree that reaches 160 km, with vertices 6.25 cm apart up close.

Builders get:

  • Whitecaps, sun glitter and a physically based sky with clouds
  • A free camera that stays above the water surface
  • URL parameters for resolution, camera pose and wind settings
  • A minified build at 61 KB, versus 102 KB unminified

Since the project was created on 16 October, it has drawn 97 forks and four open issues.

The catch: It requires a recent Chrome with WebGPU and a capable GPU, and laptops may silently fall back to integrated graphics unless forced to the dedicated one.

Use Cases
  • Game developers prototyping water shaders without adopting a full engine
  • Graphics students studying FFT ocean simulation in readable WebGPU code
  • Web designers needing a lightweight animated sea background for landing pages
