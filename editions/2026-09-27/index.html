Single-File WebGL2 Demo Delivers Photoreal Water Without Build Tools 🔗

Real-time caustics and FFT waves run in browsers using only HTML, shaders, and base64 textures

Aureliengmz/clearwater · HTML · ▲ 31 in 1d 3d old

Aureliengmz/clearwater renders photorealistic shallow water simulation in a single HTML file, requiring no external libraries, build steps, or assets. Using WebGL2 with float render targets, it implements Jerry Tessendorf’s FFT-based ocean wave model, Evan Wallace’s refracted-grid caustics, and Inigo Quilez’s seabed tiling techniques—all within client-side JavaScript and GLSL shaders.

The seabed texture is embedded as a base64-encoded JPEG at the file’s end, regenerable via a Python tool using NumPy and SciPy. Resolution dynamically adapts to maintain frame rate, and users can interact by dragging to look around or tapping to disturb the water surface.

This approach eliminates toolchain friction for developers experimenting with real-time water rendering, offering an immediately runnable reference for caustics, FFT waves, and LEAN mapping-based highlights. It serves as both a learning resource and a deployment-ready snippet for prototypes or educational demos where zero-install access matters.

The catch: The simulation is limited to shallow water effects and lacks deep-water physics, foam, or spray, making it unsuitable for full ocean scenes without extension.

Why this leads today It enables instant, no-installation photorealistic water simulation in any browser, removing barriers to real-time graphics experimentation and education through a self-contained, library-free WebGL2 implementation.

Use Cases
  • Learn real-time water rendering with FFT and caustics
  • Embed interactive water in static educational sites
  • Prototype fluid effects without build configuration

Chat On Steroids gives ChatGPT durable local workflow control across platforms 🔗

It enables multi-agent Goal/Loop workflows with file access and terminal use while respecting provider limits

totec448-spec/chat-on-steroids · TypeScript · 4.1k stars 1mo old

Chat On Steroids (CoS) is a TypeScript-based local MCP workspace that lets ChatGPT interact with your desktop — reading and editing files, running tests, and managing terminals — without invoking Codex directly. It works as a cross-platform Electron app with Chrome integration, supporting Windows, macOS, and Linux.

Instead of bypassing limits, CoS uses your existing ChatGPT conversation, sharing its usage and context boundaries.

The tool structures work through Goal, Loop, Compact & Resume, and durable multi-agent workflows. Goal tracks unfinished tasks; Loop keeps workers operating within a defined brief. Workers maintain context so they can resume where they left off. Compact & Resume preserves session and worker history when starting a fresh chat, enabling long-running projects to continue seamlessly.

Release v2.1.16 focuses on reliability: it adapts to ChatGPT’s latest UI changes, prevents chats from getting stuck, and ensures workers receive tools promptly after their first message. Message queues now time out after 15 minutes of silence to avoid permanent blocking, and chats stay linked across app restarts.

The catch: CoS depends on ChatGPT’s frontend behavior, making it fragile to UI changes — though v2.1.16 shows improved resilience — and it cannot override provider-enforced safety or usage limits, so it won’t grant extra quota or bypass restrictions.

Use Cases
  • Developers automate file edits and test runs via ChatGPT
  • Teams run parallel agents on independent code modules

A clear pattern is emerging in open source web frameworks: a shift toward type-safe, locally executable backends that decouple API contracts from runtime infrastructure. Projects like middleapi/orpc exemplify this with its TypeScript-first approach to generating end-to-end typesafe APIs without codegen, reducing boilerplate while catching contract errors at compile time.

Similarly, ollaya-dev/ollaya extends the Ollama paradigm to decision models—Laya, decider, NLI, and GLiClass—offering a TypeSafe-compatible API to run open, local reasoning engines, effectively treating AI inference as a first-class API service. This mirrors ddalcu/mlx-serve’s Zig-native LLM server for Apple Silicon, which provides OpenAI/Anthropic-compatible endpoints without Python dependencies, emphasizing performance and deployment simplicity. Beyond AI, alexgreensh/anidoodle demonstrates how declarative, code-driven art and animation—rendered identically every time—can be treated as version-controlled API outputs, blurring the line between creative tooling and backend services. Even non-AI projects like rgem227/knoweldge-base and xerrors/Yuxi lean on MCP API calls to standardize knowledge agent interactions, suggesting a broader move toward interoperable, self-hosted cognitive layers. The trend reflects a maturing desire for deterministic, auditable, and locally controllable systems where APIs are not just interfaces but enforceable contracts—powered by strong typing, local execution, and standardized agent protocols.
The catch: While promising, this cluster remains fragmented across languages (TypeScript, Python, Zig, Go) and maturity levels, with many projects lacking robust observability, long-term support, or clear migration paths from established frameworks, raising concerns about ecosystem cohesion and production readiness beyond early adopter use cases.
