Lightpanda’s Zig-Powered Browser Outpaces Chromium for AI Automation 🔗

Delivers 16x lighter, 9x faster performance via CDP without Chromium forks or patches

lightpanda-io/browser · Zig · ▲ 72 in 1d Est. 2023 · Latest: 1.0.0

Lightpanda, the headless browser written in Zig, is gaining traction among developers building AI agents and automation workflows. Unlike Puppeteer or Playwright, which rely on Chromium forks, Lightpanda is a ground-up implementation designed specifically for programmatic control.

It exposes the Chrome DevTools Protocol (CDP) server on port 9222, allowing existing automation clients to connect seamlessly while avoiding the bloat of full browser engines. Benchmarks show it requests 933 real web pages on an AWS EC2 m5.large instance with significantly lower memory and CPU overhead.

The project’s latest release introduces meaningful Web API advancements: WebAssembly.compileStreaming, Sanitizer API initial support, TextEncoder.encodeInto, and experimental ServiceWorker integration behind a flag. CORS is now enforced by default with tunable limits, and WebDriver support has been expanded for session management, element interaction, and cookie handling. These updates position Lightpanda as a viable, lightweight alternative for CI/CD pipelines, scraping, and AI-driven browser automation where startup speed and resource efficiency matter.

The catch: Lightpanda lacks native Windows and Android builds, requires glibc (excluding Alpine/musl), and its Web API coverage remains incomplete — critical for complex SPAs or legacy sites needing full browser fidelity.

Why this leads today Lightpanda introduces a headless browser built in Zig specifically for AI automation, offering a new tool that enables developers to script and scale web interactions in ways previous solutions did not support.

Runs original Switch game code at 60 fps with full touch controls and Reign of the Warlock expansion on Apple silicon

jhaizhou-ops/d2r-mobile · C · 1k stars 1d old

The jhaizhou-ops/d2r-mobile project is an open-source compatibility layer that enables players to run their own Nintendo Switch copy of Diablo II: Resurrected with the Reign of the Warlock expansion natively on iPhone, iPad, and Mac. Rather than emulating, it executes the game's existing aarch64 binary directly on Apple hardware, rewriting only the handful of instructions incompatible with Apple's kernel while leaving all other code and data unchanged.

Graphics are reimplemented via Metal with offline shader translation, and input, audio, filesystem, and system calls are handled by a minimal host layer. Touch controls are fully rebuilt for edge-to-edge iPhone and true full-screen iPad display, with controller support, power saver mode, and save sync. The latest release, v1.0.6, improves turning feel (r42) by eliminating one-frame stutter on sharp turns and increasing minimum turning speed from 180 to 360 degrees per second when using a gamepad. It also patches small memory leaks from short-lived threads, text-input dialogs, and graphics layer components, and now logs memory warnings on iOS. The no-Xcode build route now supports older devices down to A16 chips.
The catch: The project requires users to provide their own legally obtained Switch game files; it does not include or distribute any game assets, and setup involves manual steps like replacing the shell or running ./setup.sh for Xcode builds, which may pose a barrier for less technical users despite the polished end result.
