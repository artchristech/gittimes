Search Browser Strips the Web Down to Its Essentials for Focused Work 🔗

Built on macOS WebKit, it blocks trackers and ads at the network level while keeping memory use under 3 MB

driceroland/Search · Swift · 1.4k stars 5d old · Latest: v1.0.3

Search is a minimalist web browser for macOS that removes every distraction between user and content. It presents only a single input field and tabs—positioned top or left—with no toolbar, start page, or suggestion feed.

By leveraging the system’s built-in WebKit engine, the app avoids bundling Chromium, resulting in a ~3 MB download that launches instantly and consumes minimal memory.

Its design targets builders who live in browsers but reject their bloat. Search never sends typed queries until Return is pressed, and it offers reading mode (⇧⌘R) to strip pages to article text. Users can hide persistent UI elements—cookie banners, newsletter overlays—with ⇧⌘H, and the block remains effective on future visits before the page renders. Video can be lifted into a floating window (⇧⌘P) that stays above all apps. Passwords are saved only after successful login and stored in the macOS Keychain, with autofill now requiring Touch ID in v1.0.3.

Extensions operate under strict security: updates are verified against Developer ID signing and checksums, and each requests permissions anew upon update. The browser blocks third-party trackers and ad networks at the network level, preventing render work entirely. History restores instantly from prior sessions, and tabs can be pinned to shrink to icons or letters.

The catch: As a macOS-only WebKit browser, Search excludes Linux and Windows users, and its minimalist design omits advanced dev tools, making it less suitable for debugging or extension development compared to full-featured browsers.

Why this leads today It addresses a clear need among macOS developers for a lightweight, native WebKit browser that streamlines web testing and debugging without the overhead of larger alternatives.

Use Cases
  • Developers seeking distraction-free documentation reading
  • Writers needing clean article extraction from noisy sites
  • Privacy-focused users avoiding tracker-heavy mainstream browsers
