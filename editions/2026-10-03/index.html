Blueprint Animation Turns UX Redesigns Into Step-by-Step Design Stories 🔗

Reads Figma files to animate design decisions as live blueprint transitions without cutting

moguzbulbul/blueprint-animation · JavaScript · ▲ 9 in 1d 5d old · Latest: v1.3.1

moguzbulbul/blueprint-animation is a Claude Design skill that transforms static UX redesigns into animated, step-by-step blueprint explanations. It reads values directly from a Figma file—using real fonts, exported icons, and layout data—to generate a continuous animation where the screen morphs into a cyan blueprint, highlights changing components, and overlays guides, dimensions, and labels to justify each design decision.

The skill supports two modes: "Redesign," which animates a before-and-after transition by showing only the evolving parts rebuild themselves, and "Explain," which breaks down a single screen module by module with annotated blueprints. Each step focuses on one UX decision, using staggered motion and smooth performance to maintain clarity. The output is a 3–6 step narrative that shows why a design works, not just what it looks like, making it ideal for case studies, design handoffs, and social storytelling. The skill includes a QA checklist to validate animations against the Figma source before export, ensuring pixel-perfect reproduction.
The catch: The skill is currently limited to non-commercial use under CC BY-NC 4.0, requiring written permission for any commercial application, which may restrict adoption in professional design teams or agencies seeking to use it in client work or paid content.

ghdl/ghdl · VHDL · 2.9k stars Est. 2015

GHDL 6.0.

0 introduces an LLVM JIT compilation backend, enabling in-memory code generation for accelerated VHDL simulation without persistent binaries. The release provides prebuilt Docker images for ghdl:6.0.0-llvm-jit-ubuntu-24.04 and ghdl:6.0.0-gcc-ubuntu-24.04, alongside Windows ZIP and MSYS2 packages. Users can now target GCC, LLVM, mcode, or LLVM-JIT backends to compile VHDL designs into native executables for high-speed simulation. Waveform output remains supported in GHW, VCD, and FST formats, with co-simulation via VPI or VHPIDIRECT. The catch: Despite active development, 340 open issues persist, including long-standing bugs in VHDL-2008 support and limited scalability for ultra-large FPGA designs beyond Leon3/GRLib scale.

  • FPGA engineers simulating leon3/grlib SoC designs
  • Hardware teams verifying VHDL testbenches with GTKWave
  • Researchers co-simulating VHDL with C/C++ via VHPIDIRECT

Flame Engine Adds Flutter 3.47 Support for 3D Game Development 🔗

Latest patch republishes flame_3d with updated Flutter constraint to maintain compatibility.

flame-engine/flame · Dart · ▲ 2 in 1d Est. 2017 · Latest: flame_3d-v0.3.2

Flame Engine, a Dart-based game engine built for Flutter, has republished its flame_3d package to align with Flutter 3.47.

  1. The update, released as flame_3d-v0.3.2, modifies the dependency constraint to ensure compatibility with the latest Flutter SDK without introducing functional changes. This maintenance patch follows Flame’s core mission of providing Flutter developers with ready-made solutions for game loops, component systems, collision detection, and input handling. The engine supports 2D and 3D game development through official bridge packages like flame_audio, flame_behavior_tree, and flame_bloc, enabling integration with popular Flutter libraries for audio, logic routing, and state management. Developers can access live examples, tutorials, and API docs via flame-engine.org, with community support available on Discord and StackOverflow. The project remains active, with a commit just days ago and ongoing issue resolution.
    The catch: The flame_3d update is a dependency-only patch with no new features or performance improvements, offering no immediate benefit beyond continued compatibility with evolving Flutter versions.

EnTT 4.0.0 refines core concepts for faster ECS in games 🔗

Header-only library drops legacy utilities, adds enum_bitmask and cvref_unqualified concepts

skypjack/entt · C++ · 13.2k stars Est. 2017

EnTT’s v4.0.

0 release streamlines its entity-component system by removing deprecated core utilities like entt::identity and entt::popcount, replacing them with modern C++20 concepts such as enum_bitmask and cvref_unqualified. The update improves storage and component destruction performance for trivially destructible types and refines type_info and component_traits to favor concepts over SFINAE. Used in Minecraft and ArcGIS Runtime, EnTT remains a dependency-free, header-only ECS favored for data-oriented design in game dev.
The catch: Its narrow focus on game-oriented ECS may limit appeal for non-gaming systems needing broader reflection or networking features.

Use Cases
  • Game devs building high-performance entity systems in C++
  • Engine creators requiring data-oriented design with minimal dependencies
  • Developers needing fast runtime reflection for game objects and components

RodZill4 updates Material Maker with node layout and cursor enhancements 🔗

RodZill4/material-maker · GDScript · 6k stars Est. 2018

Material Maker 1.7 introduces UI refinements for its Godot-based texture authoring tool.

Users can now save/load panel layouts, toggle side panels, and use MMB to jump from linked parameters to source nodes. File dialogs show thumbnails, and node connections display hover hints. The quickbar gained keyboard shortcuts, and node seeds can be rerolled via a new graph panel button. These updates streamline procedural texture creation and 3D model painting workflows. The catch: Active development relies heavily on a single contributor, with 330 open issues indicating potential delays in addressing complex feature requests or bugs.
