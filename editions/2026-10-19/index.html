OpenCV 5.0 Ships Its First Major Rewrite in Years for Vision Builders 🔗

The C++ library now targets modern hardware and migrates 4.x code, but Android builds need a separate 16kb-page package.

opencv/opencv · C++ · ▲ 15 in 1d Est. 2012 · Latest: 5.0.0

**OpenCV 5.0.

0** is out, and it is the first major version bump since the 4.x line. For developers building computer vision pipelines, that means a new baseline for the library that underpins image processing, camera tooling and deep-learning inference across desktop, server and embedded targets.

The release centers on a published 4.x-to-5.x migration guide, which signals that the team expects real code to move, not just rebuild. Teams should budget time for that port rather than assume drop-in compatibility.

Platform notes in the release matter for shipping products:

  • Android: The original SDK was built against an older NDK and its standard C++ library is not aligned for devices with 16kb memory pages. Google Play releases should use the package with the 16kb-page-fix suffix.
  • Windows on Arm: Binaries are validated on Qualcomm Snapdragon hardware. On devices with private L2 caches, PPL auto-partitioning may fail, and the project recommends building with OpenMP instead.

The library itself is written in C++ and covers classic image processing alongside deep-learning modules, with the project's own opencv.ai services offering commercial support for teams that want it.

Project activity is steady: the last push landed today, and the repository has accumulated 2,840 open issues, a sign of wide use alongside a sizable maintenance queue.

The catch: Open issues at this volume mean fixes and edge-case behavior will take time to land, and the platform-specific caveats above show that 5.0 still needs per-target verification. Check the migration guide and test on your actual hardware before committing a production release.

Why this leads today OpenCV sits beneath much of today's computer-vision work, from factory inspection and robotics to mobile apps and machine-learning pipelines, so its changes reach more builders than any other story on today's list.

Use Cases
  • Mobile app teams shipping camera features to Google Play on 16kb-page Android devices
  • Embedded engineers porting vision pipelines to Windows-on-Arm Snapdragon hardware
  • Existing OpenCV 4.x maintainers planning a migration to the 5.x API

Opik Adds Dataset Version Viewing and Tighter Tracing for LLM Teams 🔗

Open-source Apache-2.0 platform traces agent tool calls and evaluates RAG pipelines, now with a fix for multi-decorator async tracing.

comet-ml/opik · Python · 22.7k stars Est. 2023

Teams building LLM applications need to see what their agents actually did, and whether the output was any good. Opik, the open-source observability and evaluation platform from Comet, covers that loop: tracing, evaluation datasets, LLM-as-a-judge metrics, prompt management and production monitoring, all under an Apache-2.

0 license that permits self-hosting.

The latest release, 2.2.105, lands three changes worth noting. The @track decorator now detects async functions even when they are wrapped by multiple decorators, a common failure in layered codebases where traces silently went missing. Stream logging was also repaired: usage and output are now recorded when a ResponseFailedEvent fires, so failed streaming calls leave a usable record. On the interface side, users can view an earlier dataset or test suite version without restoring it, and the Playground now keeps a prompt loaded even in a session that never opened it.

For builders, the practical value is in the trace tree. Multi-step agents and tool calls appear as nested spans, and feedback scores can be attached to traces through the Python SDK or the UI. A PyTest integration lets teams run evaluations on each commit, turning prompt or model changes into testable regressions rather than guesses.

The catch: The project has 195 open issues and is actively developed, but its surface area is large: tracing, evaluation, optimization, guardrails and dashboards in one platform. Teams that want only lightweight logging may find the self-hosted footprint heavier than they need, and the repository's rapid cadence means integration details, such as framework-specific behaviour, should be verified against the current release before production use.

Open-Source Tool Strips Bloatware From Android TVs Over Wi-Fi 🔗

Its coding-assistant workflow replaces ad-filled home screens with an Apple TV-style launcher, with nothing uninstalled and one-command restore.

Gathin23/cleanyourtv · Java · 3.8k stars 2d old

A new open-source project lets anyone remove manufacturer bloatware from an Android or Google TV without root or a cable. Users enable USB debugging, connect over the same Wi-Fi, and hand the job to a coding assistant such as Claude Code.

The assistant backs up installed packages, disables telemetry, ad services and preloaded apps with pm disable-user, then builds and installs a native launcher. Nothing is uninstalled, so a restore script can reverse every step.

The launcher replaces the sponsored home screen with a dark layout: a dock of favourite apps, a top shelf naming the focused app, and a grid of the rest. Version 2.2.0 adds theme support through config.json, optional module cards for third-party apps, and live tile refresh.

The project has 443 forks and 43 open issues, and the latest commit landed this morning. Setup takes roughly fifteen minutes.

The catch: Each TV brand ships different bloat, and the assistant must decide what to disable, so an AI agent with shell access is effectively making judgment calls on a device most owners have never inspected.

The repository contains no game program, art, audio, or keys. It holds the patch code, the addresses and hashes used to verify files, and a shader list that names shaders and bind states without shader code.

The iOS build requires iOS or iPadOS 26 and an iPhone 14 or newer. Version 1.4.3 has been reported playing on an iPhone 14 and an iPad.

The catch: the project is an independent, non-commercial effort with 12 open issues, and the README says shaders must be precompiled by players, so stutter-free performance depends on community contributions.

LeanREA Swaps Agent Tool Layer for One 8 KB Skill File 🔗

Benchmark shows 38% faster runs and 35% lower cost than the MCP-based REA it replaces

aicodeking/leanrea · Python · 870 stars 2d old

leanrea drops the MCP server layer that reverse-engineering agents usually depend on. Instead, one 8 KB skill file tells the agent which plain CLI tool is fastest for each target, supplies ready-to-paste recon commands, and lists the traps REA's code previously handled.

The agent then runs the real tools itself: asar, otool, nm, jadx, apktool, tshark, binwalk and others.

In a benchmark of four tasks run through Claude Code headless, leanrea recorded:

  • 38% less wall time than REA
  • 35% lower cost
  • 56% fewer turns
  • 60% fewer tokens, at matching accuracy

Each cell used only three repetitions, on one model and one machine. REA was tested in its best case, with deferred tool loading.

The catch: the sample is small, and the Ghidra and jadx tasks ran on Xcode tools because those were not installed.

Switch Games Now Run Natively on iPhone, iPad and Mac 🔗

Open-source project converts owned NSP files into sideloadable IPAs, skipping emulation for direct Apple-chip execution

seedds/nxnative · C · 687 stars 6d old

The seedds/nxnative project takes an NSP folder and produces an unsigned IPA that can be sideloaded onto Apple devices. It is not an emulator.

The game's own code runs directly on the Apple chip, with Switch graphics rebuilt on Metal.

The pipeline has three main parts:

  • An NSO rewriter prepares the game's binaries for native execution.
  • A Horizon host stands in for the Switch operating system's services.
  • An NVN-to-Metal layer translates Switch graphics calls. Maxwell shaders are converted to SPIR-V by Ryujinx's translator, then to Metal Shading Language via SPIRV-Cross.

Users supply their own game files and prod.keys. The repository contains no game assets. Several projects are credited, including d2r-mobile, Ryujinx, Atmosphère and LibHac.

The catch: The Legend of Zelda: Tears of the Kingdom is still being ported. It reaches the opening cave on an iPhone 15 Pro or newer running iOS 26, and frame rate remains unresolved.

  • Developers studying native execution of console binaries on Apple silicon

Nixpkgs Passes 140,000 Packages as Reproducible Builds Spread 🔗

Hydra continuously builds and tests every package before the cache serves binaries to users

NixOS/nixpkgs · Nix · 26.5k stars Est. 2012

Nixpkgs now holds more than 140,000 software packages installable through the Nix package manager. It also powers NixOS, a purely functional Linux distribution where system configuration is declared rather than mutated.

The project's pipeline is what distinguishes it. Hydra, the continuous integration system, builds and tests both the unstable master branch and the NixOS 26.05 release. Successful artifacts are published to cache.nixos.org, and only builds that pass are distributed through Nix channels.

For builders, the practical effect is that a package set can be pinned, rebuilt and rolled back deterministically across machines.

The project's activity is high: the repository records 22,171 open issues and 20,430 forks, with a commit pushed within the last day.

The catch: the sheer breadth of the collection means the backlog is large, and reviewer bandwidth, not code volume, is the constraint on how quickly changes land.
