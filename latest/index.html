AI-Generated Motion Design Replaces Assets with Pure Code 🔗

Fifteen 10-second films made entirely from SVG, Canvas, and WebGL prompts by Claude Opus 5.5

Vincentwei1021/mg-styles-15 · Python · ▲ 70 in 1d 6d old

Vincentwei1021/mg-styles-15 delivers fifteen 10-second motion-design films, each generated not from rendered video or AI image models, but from executable code written by Claude Opus 5.5 in response to a single prompt per style.

The project publishes the full source, style notes, and exact prompts used to create each piece, spanning techniques from frame-by-frame cel animation and isometric 2.5D to 3D renders using Blender and WebGL. Every film renders dynamically via window.renderAt(t), outputting SVG, Canvas, or Three.js scenes frame by frame, with audio synthesized in audio.py from 103 recorded instrument samples. No raster images or video generation models are used—visuals and sound are procedurally generated, making each film infinitely scalable and editable at the code level. Developers can inspect, modify, or reprompt the animations to create derivative works, turning motion design into a transparent, code-first discipline. The repository includes detailed build instructions using headless Chrome and ffmpeg to compile frames and soundtracks into final films, enabling reproducibility and local experimentation.
The catch: The project relies heavily on Claude Opus 5.5’s specific prompt interpretation and lacks automated validation for prompt-to-output consistency, raising questions about long-term maintainability and reproducibility across model updates or forks.

Use Cases
  • Learn motion design by reverse-engineering AI-generated code
  • Generate custom animated logos using procedural SVG techniques
  • Create editable background visuals for web apps without video assets

Source: Vincentwei1021/mg-styles-15 — based on the project README.

Rust-based NVIDIA driver enables Metal on macOS Sequoia for Intel Macs 🔗

Supports RTX 20/30/40/50 series via open GPU modules and custom boot integration

nullmoth/nvidia-macos-driver · Rust · 756 stars 1d old

The nullmoth/nvidia-macos-driver project brings Metal support to NVIDIA GeForce RTX 16-series and later GPUs on Intel-based Macs running macOS 15 Sequoia through OpenCore. Built in Rust, it leverages NVIDIA’s open r610 GPU kernel modules to implement display and compute interfaces via NVRMFB, NVAccel, and NVRMAGDC components.

The driver enables WindowServer composition and Metal-accelerated graphics where Apple’s native drivers lack support.

Installation requires a verified OpenCore setup, after which users download the driver package and helper tool (1401) to inject kernel extensions. The latest release, v1.0.18, improves reliability by retaining diagnostic logs locally after failed uploads and enforcing strict SHA-256 verification for crash reports. It also adds safeguards against silent failures during setup, ensuring administrators see explicit errors when authorization or file saving fails.

This driver fills a critical gap for developers and power users who rely on NVIDIA hardware for machine learning, video rendering, or GPU-accelerated workflows on otherwise unsupported Mac hardware.

The catch: The driver remains experimental, with limited real-world validation across hardware configurations and potential instability under heavy or sustained GPU loads.

GitHub project recreates authentic Commodore 64 keycap lettering as usable desktop and web fonts 🔗

Font includes uppercase, numbers, punctuation, PETSCII graphics, and Hungarian accents from physical keycap photos

szabadkai/c64-keyboard-font · Python · 536 stars 3d old

The szabadkai/c64-keyboard-font project reconstructs Commodore 64 keycap lettering from photographs, delivering clean, proportionally consistent outlines as TTF, OTF, and webfont formats. It accurately reproduces uppercase letters, numbers, punctuation, arrows, £, π, selected accented characters including Hungarian letters, function-key labels f1–f12, and all 63 PETSCII graphic front legends.

Lowercase input displays as uppercase to match the original keycap design. Users can test symbols via an online preview or local preview.html, then copy-pasted text requires the installed font to render correctly. The project avoids tracing screen bitmap fonts, instead modeling printed key legends using reference dimensions from the Ultimate Commodore 64 Repository. The catch: The font omits lowercase glyphs entirely, limiting use to all-caps or PETSCII-mode text unless users accept uppercase substitution for lowercase input.

Supabase Pipelines Streams Postgres Changes to BigQuery in Near Real Time 🔗

New CDC service enables analytics teams to sync database events without custom ETL code

supabase/supabase · TypeScript · ▲ 37 in 1d Est. 2019 · Latest: v1.26.08

Supabase launched Pipelines in public alpha, a managed change data capture (CDC) service that streams Postgres inserts, updates, and deletes to BigQuery with sub-second latency. Configured entirely through the Supabase Dashboard, Pipelines eliminates the need for developers to build and maintain custom ETL scripts or third-party tools like Debezium for basic analytics syncing.

The service uses Postgres’ native logical replication to detect changes, converts them to JSON, and forwards them via secure, encrypted channels to BigQuery datasets.

This release tightens Supabase’s integration with modern data stacks, letting teams trigger downstream workflows—such as dbt models or Looker dashboards—directly from database events. Paid plan users gain access immediately, with no additional infrastructure setup required. Pipelines complements existing Supabase features like Realtime subscriptions and Edge Functions by offering a durable, scalable path for analytical use cases where low-latency UI updates aren’t the priority.

The catch: Pipelines currently supports only BigQuery as a destination, limiting teams using Snowflake, Redshift, or self-hosted data warehouses who must still rely on custom solutions or wait for future connector expansions.

0 on October 5, 2026, addressing two key issues. First, .mjz archives now consistently use forward slashes on Windows, resolving path errors when sharing models across platforms. Second, and more significantly, the actuator dampratio parameter now computes reflected inertia using operational-space inertia $(J M^{-1} J^T)^{-1}$, averaged across force outputs. This change accounts for tendon dynamics, armature effects, and off-diagonal inertial coupling — critical for accurate simulation of complex actuators like orientation drives or differential mechanisms. The release includes no new features beyond these fixes, but the dampratio revision alters existing behavior — users upgrading must revisit actuator tuning.
The catch: The dampratio change is a breaking API adjustment; existing models may require re-tuning of actuator parameters to maintain intended dynamics, with no automated migration path provided.
