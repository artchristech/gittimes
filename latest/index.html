Command-line JSON processor jq gains critical security hardening in 1.8.2 patch 🔗

New release patches nine CVEs including heap overflow and hash collision DoS vulnerabilities

jqlang/jq · C · ▲ 15 in 1d Est. 2012 · Latest: jq-1.8.2

jq remains the essential tool for developers manipulating JSON data directly in terminals, offering sed-like filtering without dependencies. Its portable C implementation processes streams instantly, transforming complex nested structures with expressions like `.

users[] | select(.active) | .name`. The project’s strength lies in composability — chaining operations to extract, reshape, or validate data from APIs, logs, or config files in a single pipeline.

The 1.8.2 update focuses exclusively on security, addressing flaws that could crash systems or leak data via malicious JSON inputs. Key fixes include heap buffer overflow protections in string handling, stack depth limits for path operations, and hash seed randomization to thwart denial-of-service attacks. These patches harden jq against real-world threats where untrusted data enters pipelines — a common scenario in DevOps automation and webhook processing.

Despite its ubiquity, jq’s learning curve steeps with advanced features like recursion and object constructors. Newcomers often struggle with its terse syntax versus more verbose alternatives like Python or JavaScript tooling.

The catch: Mastering jq’s full potential requires significant time investment in its unique query language, creating a barrier for teams needing immediate JSON processing without domain-specific expertise.

Why this leads today jq’s lightweight, composable command-line JSON processing has become essential in DevOps and automation, filling a critical gap where heavier tools once slowed pipelines and limited scalability.

Use Cases

BRUTAL Gives C# Developers Direct Access to Vulkan and Native APIs 🔗

Enables full engine control without royalties, powering Kitten Space Agency and RimWorld's Waylith

ahwootech/BRUTAL · C# · 582 stars 0d old

BRUTAL is a free, open-source C# framework that provides direct access to native APIs and Vulkan, letting developers build games or custom engines from the ground up. It includes a custom interop layer, math, memory management, job scheduling, and bindings for libraries like GLFW, Dear ImGui, FMOD, RakNet, Jolt, and Box2D.

Unlike Unity or Godot, BRUTAL makes no architectural decisions — developers write their own stack and choose their own NuGet packages. It’s used in production: Kitten Space Agency was built directly on BRUTAL, and Ludeon used it to create RimWorld’s Waylith engine, moving the game off Unity. The framework avoids unnecessary allocations, uses unmanaged memory and unsafe code where appropriate, and targets the latest C# and Vulkan. Licensed under MIT, it requires only attribution, no royalties, and allows forking if maintainers diverge from community interests.
The catch: BRUTAL demands deep technical knowledge — developers must know what they want to build first, as it offers no high-level abstractions or opinionated workflows, making it considerably harder to use than mainstream engines for conventional games.

Use Cases
  • Build a custom 2D game engine with Vulkan rendering
  • Create a space simulation using C# and native physics
  • Develop a moddable game with ImGui tools and RakNet multiplayer

luanti-org/luanti · C++ · 13.7k stars Est. 2011

Luanti, the open-source voxel game engine formerly known as Minetest, released version 5.17.

0 to fix critical security vulnerabilities affecting both client and server components. The patch addresses exploitable flaws that could allow remote code execution or denial-of-service attacks, prompting an urgent upgrade advisory from maintainers. Built in C++ with Lua modding support, Luanti powers user-generated voxel worlds across Windows, Linux, and macOS, with Docker options for server deployment. Despite 15 years of development, the project carries 1,512 open issues and a recent commit just one day ago, indicating sustained but strained maintenance.
The catch: The engine’s reliance on volunteer contributions creates uncertainty around long-term security responsiveness and feature stability for production-grade game deployment.

Openage v0.6.0 Adds Flow Field Pathfinding and Activity System for AoE2 Clone 🔗

Release enables smoother unit movement and moddable behavior via node graphs and API

SFTtech/openage · Python · 14.5k stars Est. 2013

The openage project released v0.6.

0, introducing a flow field pathfinder for smoother terrain navigation and an activity system using node graphs to configure unit behavior via its Python API. Modders can now load terrain graphics from modpacks through the same interface. Built with Python, Cython, Qt6, and OpenGL, the engine aims to replicate Age of Empires II’s Genie Engine without binary compatibility. Despite 13 years of development, gameplay remains non-functional in core loops, per the team’s own admission. The catch: **core gameplay systems are still incomplete, limiting real-world use to experimentation and modding rather than playable matches.

Use Cases
  • Modders creating custom AoE2-style campaigns with Python scripts
  • Developers studying ECS patterns in open-source RTS engine design
  • Researchers testing flow field pathfinding in historical game contexts

MustardOS/internal Manages Core System Infrastructure for Embedded OS 🔗

Repository updated daily with POSIX scripts and config partitions driving kiosk and frontend systems

MustardOS/internal · GLSL · 114 stars Est. 2024

MustardOS/internal holds the foundational layer of MustardOS, including device-specific configurations, global settings, and the init system that moves the content partition on first install. It provides symlinks for SFTPGo browsing, shared resources for internal applications, and marker files for update tracking.

The frontend is compiled externally, while kiosk values and POSIX-compliant scripts form the operational backbone. Recent activity shows consistent maintenance, with the last commit just one day ago.
The catch: Reliance on external frontend compilation creates a dependency chain that complicates air-gapped or offline deployment scenarios.

Use Cases
  • Embedded developers configuring device-specific hardware profiles
  • System integrators deploying SFTPGo-accessible kiosk interfaces
  • Maintainers updating archive markers during OTA update cycles
